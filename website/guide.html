Getting started

Install & build

GreenMeasurer currently targets Linux. You need a C compiler, Make and Python 3.11 or Python with tomli. Hardware backends have optional dependencies: Intel CPU uses powercap and raplcap; NVIDIA uses NVML. Read scripts/install.sh before using it to install dependencies.

git clone https://github.com/simaocunha71/GreenMeasurer.git
cd GreenMeasurer
make -C src VERBOSE=1
./src/main --list-metrics

The verbose build explains which optional backends were skipped. Intel RAPL MSR access may require loading the msr kernel module and elevated permissions. A built backend is not a guarantee that its hardware or every metric is available.

Make your first measurement

Edit configuration.toml in the repository root. Replace the placeholder command with your program:

[measurement]
mode = "standard"
command = "sleep 1"
language = "Shell"
program = "my-program"
output = "measurements.csv"
repetitions = 3
sleep_seconds = 0
powercap = -1

[metrics]
select = ["system.cores", "cpu.Package"]

Generate into a directory that does not already exist, then run the executable separately from the repository root:

./src/main --directory my-build
./my-build/greenmeasurer

Use ./src/main --config path/to/file.toml --directory my-build for a different file. Generation compiles but does not execute the workload. The executable embeds the configuration: after editing the TOML, generate again in a new directory. A successful measurement replaces its configured CSV.

For a complete example of using GreenMeasurer, follow the usage walkthrough from a sample program through standard and overtime CSVs. Ready-made test configurations are in configurations/; run their executables from the repository root so shared relative paths resolve as intended.

Choose a mode

ModeWhat it doesResult
standardRuns the command for the configured repetitions.One row per measured execution.
overtimeRuns once and samples sequentially while it executes.One row per sampling window.
temperature-calibrationWaits for a settling period and reads CPU temperature.A baseline text file.
powercap-calibrationMeasures an existing-limit baseline and a range of power limits.A CSV and, when available, a summary.

For overtime, set interval_us to the pause between sampling cycles. Reads and scheduling add time, so it is not a guaranteed period. Window energy is reported per interval, not as instantaneous power. Sampling has a finite capacity of 262,144 rows.

Temperature baseline

All measurement and calibration modes require a readable CPU temperature from the selected CPU backend. An unavailable or invalid reading stops execution before the workload. If the baseline file is missing, a measurement creates it after the configured settling time.

[measurement]
mode = "temperature-calibration"
sleep_seconds = 10
calibration_file = "temperature.txt"

In measurements, variance controls how far above the baseline the CPU can be before a run starts. Relative output and baseline paths resolve from the working directory where the executable runs.

Powercap & calibration

Hardware state

Powercap controls can change real package limits. The desired cleanup behaviour has not been confirmed on hardware: a calibration previously left a 2 W limit visible. Do not assume limits are removed; inspect RAPL state before and after a run.

powercap = -1 leaves existing limits unchanged. A calibration baseline labelled -1 therefore uses the limits already in force; it is not necessarily uncapped. The Intel calibration code attempts to restore the prior limits after each sweep point. Firmware or other controls may impose additional limits.

The current Intel backend does not expose the optional commit callback required by the configured standard and overtime paths for a positive powercap. Those runs report an unsupported-powercapping error rather than applying the requested cap. Calibration uses a separate backend callback. Confirm your checkout before relying on powercap behaviour.

for file in /sys/class/powercap/intel-rapl:0/{enabled,constraint_0_power_limit_uw,constraint_1_power_limit_uw}; do
    echo "$file: $(cat "$file")"
done

This reads package 0 only; a multi-package host may expose additional zones. Values are in microwatts. Only use power limits supported by your hardware and account for permissions and external power-management software.

Use python3 scripts/validate_config.py path/to/config.toml to validate without running a workload. Source and adapter paths are relative to the TOML; output paths are relative to the execution working directory. See the repository README for external metric configuration.

When a metric is missing

Run ./src/main --list-metrics to inspect compiled plugins. To see runtime detection details, run a generated executable with GREENMEASURER_VERBOSE_BACKENDS=1. Check backend build dependencies, hardware support and permissions.

Metrics unavailable at preflight are skipped with a warning; readings that fail later are recorded as NOT_SUPPORTED. CPU package energy includes other activity in the same hardware domain. It is not process-exclusive, and overlapping domains should not be added together.
