01 / Setup

Generate, then run

Use Linux, a C compiler and Python 3.11 or Python with tomli. Optional device libraries have their own development dependencies; the build skips libraries whose required headers are missing. See the repository README for requirements.

make -C src
python3 scripts/weave.py examples/system/config.toml -o generated-experiment
./generated-experiment/greenmeasurer --help
./generated-experiment/greenmeasurer --aggregate \
  -command "true" -language Shell -program true -output result.csv \
  -n_times 1 -sleep-secs 0 -time_out_limit 0 --Time.WallClock --System.Cores

Generation compiles the executable but does not execute the workload. Missing dependencies or aspect build failures are reported and the affected aspects are skipped; use --help to see available flags. Without -o, the output is generated-<config name> alongside the TOML. Runtime hardware access may require additional permissions.

02 / Configuration

Compose the aspects

The TOML contains aspects only. A metric aspect declares one reader; a separate powercap aspect declares control hooks and no reader. Both declare a header and may specify a library, setup and teardown. A failed setup emits a warning and removes that aspect from the run. Explicit calibration fails if its required aspect is unavailable.

[[aspect]]
name = "System.Cores"
header = "../src/devices/linux/system.h"
lib = "../src/devices/libgm_system.a"
read = "double system_get_core_count()"
kind = "gauge"
unit = "cores"

Paths in the TOML are relative to that TOML; workload, output and baseline paths are relative to the working directory. Reweave after changing the TOML. Pass the mode, command, repetitions, output and other execution options when running the executable.

Select metric aspects explicitly with flags such as --System.Cores, or use --no-metrics. Powercap control has its own flag and can be selected with --no-metrics. Thermal control is selected separately from temperature metrics. With no active aspects, the executable runs -command once using system(), without a CSV, repetitions or timeout.

For adaptable configurations, see the combined TOML and the intel/, nvidia/ and system/ folders in examples/. The NVIDIA and system examples do not depend on Intel libraries. Temperature calibration does not run the workload. For an explanation of every TOML field, see the configuration reference.

03 / Measure

Aggregate and over-time

In aggregate mode, aspects remain active without sampling threads. Execution time appears only if a duration aspect such as --Time.WallClock is selected. Counter metrics are reported as end minus start; gauges and durations use their final reading. In over-time mode, the runtime starts one sampling thread per selected metric aspect. Powercap control has no sampling thread or metric column. Readers from the same header are serialized; libraries used through different headers must support concurrent reads. The CSV always aligns samples on a common Timestamp_ms grid; counters are raw readings.

Pass -interval-ms for over-time sampling, -n_times for repetitions and -sleep-secs for pauses. The interval is a target, not a guarantee of exact timing. Output appends to the CSV only when its header matches the selected aspects and mode.

The generator's --max-samples sets the per-metric capacity at compile time. Exceeding it aborts the measurement. See interpreting results for unavailable values and scope.

04 / Calibrate

Temperature baseline

Declare temperature aspects with thermal = true. Intel CPU temperature has its own library and libsensors dependency; Intel energy metrics do not require it. Select each temperature explicitly and supply a separate -calib-file ASPECT=PATH. --temperature-calibration waits -sleep-secs and overwrites each specified baseline with one reading; it does not run the workload.

Temperature metrics are informational unless control is selected separately with -temperature-control ASPECT. Repeat it for each controlled sensor and provide its -calib-file ASPECT=PATH and a shared -variance. A controlled sensor need not be selected as a metric. Before each run, every available controlled temperature must be at most its own baseline plus that variance. Missing files are calibrated first; invalid files for available sensors fail the run. An unavailable controlled sensor disables its own control and repetition pauses with a warning; other available sensors remain controlled. Explicit temperature calibration fails if a selected sensor is unavailable.

05 / Control

Power limits and calibration

Select a declared control aspect such as --IntelCPU.Powercap and pass the required -powercap as a comma-separated list in watts. Without a selected control, omit -powercap; limits are unchanged and the CSV uses -1. The Intel control has its own library and dependencies; without the aspect they are not linked. Positive limits require paired powercap_set and powercap_restore hooks. With the Intel control selected, -1 applies the saved per-machine baseline. Select at most one powercap control aspect.

The Intel implementation stores the RAPL package/die limits and enabled state in /var/lib/greenmeasurer/intel-rapl-baseline. When powercap is first used, it loads that file or, if missing, saves the current state before changing limits. This happens during powercap setup, not ordinary aspect initialization; the saved state is not necessarily a factory or boot-time default.

--powercap-calibration requires an explicitly selected powercap aspect with a calibration hook and a runtime -range MIN-MAX. The supplied Intel implementation measures the baseline and each integer watt value in that range. Optional -compile_cmd compiles the workload first.

Use with care

Powercap operations alter hardware limits and may require privileges. Review the range, output paths and device requirements before running. Calibration may replace its output file.

Troubleshooting

  • If generation fails, check TOML syntax, declarations, paths relative to the TOML, and whether required libraries were built.
  • If a reading is unavailable, check hardware, drivers and permissions.
  • For each controlled temperature, check its sensor and separate baseline file.
  • Run the executable with --help to see its options and aspect flags.
