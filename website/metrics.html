01 / Declare

Readers, not a fixed catalogue

A metric is a no-argument C function declared in [[aspect.metric]]. Its configured name, return type, kind and unit determine the generated flag, storage and CSV column. A counter is cumulative; a gauge is an instantaneous value. The default kind is gauge.

The following readers are examples from optional libraries in src/devices/, not built-in metrics. Add them to an aspect declaration before using them; names in the CSV come from your TOML, not the function names. Hardware and permissions determine availability.

[[aspect.metric]]
name = "Package"
read = "double intel_cpu_get_package()"
kind = "counter"
unit = "J"

For a device named IntelCPU, this produces the flag --IntelCPU.Package and column IntelCPU.Package_J. See the declaration reference.

02 / Optional library

Intel CPU

Intel CPU readers expose cumulative energy for package, core and DRAM domains, as well as mean current core temperature. The library also provides thermal and powercap hooks. Energy domains can overlap and are not measurements of a single process.

ReaderQuantitySuggested kind
intel_cpu_get_package()Package energy, Jcounter
intel_cpu_get_core()Core energy, Jcounter
intel_cpu_get_dram()DRAM energy, Jcounter
intel_cpu_get_temperature()Mean core temperature, °Cgauge

GPUs

The NVIDIA library uses NVML; Intel GPU readings depend on available RAPL and sensor support. The Intel GPU temperature reader selects the first hwmon sensor labelled GPU, so verify its source on systems with multiple GPUs.

System

ReaderQuantitySuggested kind

system_get_running_processes()Runnable system processesgauge
system_get_workload_processes()Live processes in the workload treegauge

Workload-scoped readers use the workload PID provided by the runtime. In standard mode gauges are final readings, not peaks or averages across the run.

05 / Interpret

Read the CSV

Each row starts with Language, Program, Powercap and a time column, followed by selected, active metrics. Time_ms is the elapsed run time in standard mode; Timestamp_ms is the aligned sample time in over-time mode.

Standard counter values are end minus start, while over-time counter values are raw readings. Counters may wrap or reset. A negative reading means unavailable and is written as NOT_SUPPORTED; device initialization and available columns can vary by machine. Avoid appending runs with different column schemas to the same file.
