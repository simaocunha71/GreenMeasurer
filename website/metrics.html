Reading the tables

Use the name in the first column in [metrics] select. A backend function name can also be selected with the same category prefix, for example cpu.intel_metric_package. CSV columns use the metric name and unit, such as cpu.Package_J.

window Counter delta for a measurement window. gauge A current reading. peak The highest sampled value. Hardware support and permissions determine which metrics can actually be read.

make -C src
./src/main --list-metrics
./src/main --list-metrics cpu intel

Listing describes compiled plugins without testing each reading. Only load plugins from trusted directories.

Backend / Intel

CPU

Energy counters use Intel RAPL MSRs. Temperature comes from Linux coretemp hwmon or sensors; it is not a RAPL metric. View definitions ↗

TOML nameKindReading functionMeaning
cpu.Packagewindow · Jintel_metric_packagePackage energy from the package MSR.
cpu.Corewindow · Jintel_metric_coreCore-domain energy from RAPL PP0.
cpu.DRAMwindow · Jintel_metric_dramDRAM-domain energy, when exposed.
cpu.Temperaturegauge · °Cintel_metric_temperatureAverage available CPU core temperature.

Package and core domains overlap. Do not sum them as independent energy sources. Counter deltas handle one 32-bit wrap; multiple wraps within one window cannot be detected.

Understand the CSV

Standard uses Time_ms per run; overtime uses Timestamp_ms relative to the run start. The Language, Program and Powercap columns record configured labels and the requested cap. -1 means existing limits were left unchanged.

Unavailable metrics may be skipped at preflight. If a later read fails, its value is recorded as NOT_SUPPORTED. With select = "all", the resulting schema can differ between machines and runs.
