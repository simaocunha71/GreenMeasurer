01 / Architecture

Weaving measurement concerns

scripts/weave.py validates a TOML file, generates C code specialized to its declarations, and compiles it with the shared runtime and specified device code. This is aspect-oriented composition of measurement concerns: the workload is run as a separate command, not rewritten or instrumented by the weaver.

INPUT

TOML + device code

Experiment defaults, reader functions and optional hooks.

GENERATED

Aspect code + glue

Per-aspect sampling code and static metric arrays, plus registration and flags.

LINKED

Executable

Shared runtime and declared libraries coordinate the workload and output.

In over-time mode the runtime calls each active aspect's start and stop functions; the thread is created and joined inside its generated <Aspect>.c. Standard mode keeps the aspects active but uses no sampling threads. The source of truth for the runtime contract is gm_aspect.h.

02 / TOML

Read a configuration

A TOML file has one [measurement] table, followed by zero or more [[aspect]] tables. Each aspect has one or more [[aspect.metric]] tables; each metric belongs to the most recently declared aspect. The old [[device]] format is no longer accepted. This example is based on the NVIDIA over-time configuration:

[measurement]
mode = "over-time"
calibration_file = "temperature-baseline.txt"
command = "python3 Languages/Python/Fibonacci/fibonacci.py 30"
language = "Python"
program = "fibonacci-30"
output = "example-nvidia-overtime.csv"
repetitions = 1
interval_ms = 10

[[aspect]]
name = "NvidiaGPU"
optional = true
lib = "../../src/devices/libgm_nvidia_gpu.a"
header = "../../src/devices/linux/gpu/nvidia/nvidia_gpu.h"
link = ["-lnvidia-ml"]
setup = "int nvidia_begin()"
teardown = "void nvidia_end()"

[[aspect.metric]]
name = "Energy"
read = "double nvidia_get_energy()"
kind = "counter"
unit = "J"

For example, name = "NvidiaGPU" names the aspect, while name = "Energy" names one metric within it. Together they produce the flag --NvidiaGPU.Energy and CSV column NvidiaGPU.Energy_J. The complete example declares additional metrics.

Relative header and lib paths are resolved from the TOML's directory. The workload command, CSV and calibration paths are resolved from the generated executable's working directory. Re-generate after editing the TOML.

On a small screen, scroll the tables horizontally to see every column.

03 / Field reference

[measurement]

Defines the experiment. mode and a non-empty calibration_file path are required in every TOML; workload modes also need a non-empty command at runtime. Integer ranges below apply to TOML values.

FieldMeaning and default
modeRequired string: standard, over-time, temperature-calibration or powercap-calibration. See the mode guide.
commandWorkload command executed through a shell, for example python3 program.py 30. Required at runtime except for temperature calibration; no default command.
languageText label in the CSV, such as Python; default Unknown. It does not choose an interpreter.
programText label identifying the workload in the CSV; default program. Neither label may contain a comma, double quote or newline.
outputOutput CSV path. Default measurements.csv, or powercap_calibration.csv for a generated powercap-calibration executable. Standard and over-time append; calibration may replace its output.
interval_msOver-time sampling interval in milliseconds, from 1 to 4,294,967; default 1. Not valid in a powercap-calibration TOML.
repetitionsNumber of workload runs per powercap, from 1 to 1,000,000; default 1.
sleep_secondsPause between repetitions, or wait before taking a temperature baseline; 0–86,400 seconds, default 0.
powercapInteger or list of up to 128 distinct values for standard and over-time, in watts. Each is -1 or at least 1; default -1. Positive limits require paired device hooks. Not valid in powercap-calibration TOML.
varianceAllowed temperature above the baseline before a run, in °C; integer 0–1,000, default 5. It matters when a thermal hook is available.
calibration_fileRequired non-empty path to the temperature baseline; there is no default. Temperature calibration overwrites it; a thermal-controlled run creates it if missing. The path is relative to the generated executable's working directory unless absolute.
powercap_min, powercap_maxInclusive watt range for powercap calibration only. Both are required for that mode; positive integers with min ≤ max and fewer than 128 values in the range.
timeout_hoursOptional per-workload timeout in hours, from 1 to 1,000. Without it, powercap calibration uses one hour; other modes have no workload timeout.
compile_commandOptional non-empty shell command to compile the workload before a powercap calibration; not valid in other TOML modes.

04 / Field reference

[[aspect]]

Declares where the aspect functions come from and which lifecycle or control hooks to use. It must contain at least one metric. Without any aspects, the generated executable runs the configured command once using system(), without CSV, timeout or command-line overrides; only mode, calibration_file and command are accepted.

FieldMeaning and default
nameRequired unique aspect identifier, for example NvidiaGPU. It must use ASCII letters, digits and underscores, beginning with a letter or underscore.
headerRequired path to an existing C header declaring the functions. Relative to the TOML file.
libOptional path to an existing .c, .o, .a or .so providing the functions, relative to the TOML. Other linked sources may provide them instead.
linkOptional array of extra linker flags such as ["-lnvidia-ml"] or ["-L/usr/local/lib", "-lsensors"]. Entries must use the supported -l or -L form.
optionalBoolean, default false. If true and setup fails, a warning is emitted, selected columns contain NOT_SUPPORTED, and its hooks are disabled. The header and libraries must still exist and link at generation time.
setupOptional no-argument void or int function signature called before using the device, for example int nvidia_begin(). A non-zero int means setup failed.
teardownOptional no-argument void or int function signature called to release a successfully initialized device. Any return value is ignored.
thermalOptional numeric no-argument reader signature for the temperature baseline and thermal waiting, in °C; required by temperature calibration.
powercap_set, powercap_restoreOptional signatures int set(int) and int restore(). Declare both together; zero means success. They apply and restore a limit for standard and over-time runs.
powercap_calibrationName of a function matching GmCalibratePowercapFn; required for powercap calibration. This is a function name, not a signature string.

When several devices declare control hooks, the runtime chooses the first available thermal hook, the first available powercap set/restore pair and the first available calibration hook, independently, in TOML order. It does not apply multiple devices' powercaps simultaneously. The supplied NVIDIA library provides readers, not powercap hooks.

05 / Field reference

[[aspect.metric]]

Declares one reading for the preceding aspect. Metrics are selected by default unless the generated executable is given specific metric flags or --no-metrics.

FieldMeaning and default
nameRequired C identifier, unique within this aspect, such as Energy. Together with the aspect name it defines the flag and CSV column prefix.
readRequired no-argument C function signature, for example double nvidia_get_energy(). The header and linked code must provide it. Supported return types include float, double and the integer types listed in the weaver.
kindcounter for a cumulative reading or gauge for an instantaneous reading; default gauge. Standard mode uses the counter difference or final gauge value; over-time records raw readings.
unitOptional label appended to the CSV column after an underscore, such as J, W, C, % or MiB. Default is empty. Allowed characters are letters, digits, _, %, ., / and -; the label does not convert values.

Negative or non-finite readings are written as NOT_SUPPORTED. The metrics page describes the optional library readers and their units.

06 / Hooks

Optional aspect hooks

KeyContract
setup, teardownNo-argument void or int functions; non-zero setup means failure.
thermalNo-argument numeric reader for thermal control, in °C.
powercap_set, powercap_restoreDeclare together: int set(int) and int restore(); return zero on success.
powercap_calibrationFunction name matching GmCalibratePowercapFn in gm_aspect.h; required for powercap calibration.

The runtime supplies runTesting() for calibration implementations such as the Intel CPU library. Hook-only devices whose setup fails lose their hooks with a warning. A thermal hook enables baseline-based waiting; powercap hooks may change hardware state.

07 / Extend

Bring your own device code

  1. Implement and expose no-argument numeric readers in a C header and a source file or library.
  2. Optionally expose setup, teardown, thermal and powercap functions with the required signatures.
  3. Declare the file paths, link flags, hooks and each desired metric in the TOML.
  4. Run the weaver and test on the target machine. Except for configured powercap-calibration executables, use --help to inspect the available flags.

The existing device libraries are examples, not mandatory backends. gm_workload_pid is available to readers that need the root PID of the workload process tree.

08 / Commands

Build and test

make -C src
python3 scripts/weave.py config.toml -o generated-experiment
./generated-experiment/greenmeasurer --help
make -C src test
make -C src clean

The example above assumes a standard or over-time configuration; configured powercap-calibration executables do not accept arguments. make -C src builds available optional device libraries. The clean target removes their generated objects and archives and the C test executable. Batch generation, sequence execution and analysis utilities are documented in scripts/README.md.
