Getting started / Walkthrough

Using GreenMeasurer

Follow a complete measurement: configure a program, run it in standard and over-time modes, and inspect the resulting CSVs.

On this pageBefore you start1. Write the program2. Configure3. Generate & run4. Read the CSVsUse your own program

Before you start

This walkthrough uses a small recursive Fibonacci program in Python only as an example workload. The same GreenMeasurer workflow applies to other foreground programs and languages: choose a command, configure measurements, generate an executable and run it.

Run the commands below from the GreenMeasurer repository root. Follow the installation guide first: this example requires Python, the built launcher and a working CPU backend with a readable temperature sensor. Intel package energy also needs the Intel RAPL backend and permission to read MSRs.

The example uses powercap = -1, which applies GreenMeasurer's saved per-machine RAPL baseline. On first use, that baseline is captured from the current hardware limits; verify they are the values you want before the first run. It does not run powercap calibration.

The commands create fibonacci.py, two TOML files, two build directories, a temperature baseline and two CSVs in the repository root. The file-creation commands and successful measurements overwrite files with those names. Choose different names if you need to keep existing files.

Step 01

Write the workload

Create a deliberately recursive implementation without memoization. It prints 9227465 for fibonacci(35).

cat > fibonacci.py <<'PY'
def fibonacci(n):
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)


if __name__ == "__main__":
    print(fibonacci(35))
PY

python3 fibonacci.py

Increase or decrease 35 to adjust the workload duration; recursive Fibonacci becomes much slower as the input increases. This program is intentionally inefficient so that it can be sampled.

Step 02

Create two configurations

First, configure three standard measurements. Each execution produces one row. The first run creates fibonacci-temperature.txt if it does not exist.

cat > fibonacci-standard.toml <<'TOML'
[measurement]
mode = "standard"
command = "python3 fibonacci.py"
language = "Python"
program = "fibonacci"
output = "fibonacci-standard.csv"
repetitions = 3
timeout_hours = 1
sleep_seconds = 0
variance = 5
powercap = -1
calibration_file = "fibonacci-temperature.txt"

[metrics]
select = ["system.cores", "cpu.Package", "cpu.Temperature"]
TOML

Now configure over-time sampling for one execution of the same program. It uses the same temperature baseline and writes a separate CSV.

cat > fibonacci-overtime.toml <<'TOML'
[measurement]
mode = "over-time"
command = "python3 fibonacci.py"
language = "Python"
program = "fibonacci"
output = "fibonacci-overtime.csv"
interval_ms = 10
sleep_seconds = 0
variance = 5
powercap = -1
calibration_file = "fibonacci-temperature.txt"

[metrics]
select = ["system.cores", "cpu.Package", "cpu.Temperature"]
TOML

These selections assume an Intel CPU backend. Run ./src/main --list-metrics to inspect compiled backend names. On another CPU backend, use the metrics it declares, or select only system.cores in both files; a readable CPU temperature is still required. Without an available energy metric the CSV cannot report energy.

Step 03

Generate and measure

make -C src
./src/main --config fibonacci-standard.toml --directory fibonacci-standard-build
./src/main --config fibonacci-overtime.toml --directory fibonacci-overtime-build

./fibonacci-standard-build/greenmeasurer
./fibonacci-overtime-build/greenmeasurer

Generation compiles an executable but does not run Fibonacci. The two build directories must not already exist. If you change a TOML file, generate a new executable in a new directory.

On Intel systems, applying the saved RAPL baseline may require elevated privileges. Run the generated executables with sudo when needed, for example sudo ./fibonacci-standard-build/greenmeasurer. Files created with sudo may be owned by root. Use elevation only when needed and inspect trusted commands before running them.

If CPU temperature cannot be read, GreenMeasurer reports an error and does not start the workload. It can wait between runs for the CPU to cool to the baseline plus variance. With sleep_seconds = 0 the baseline is immediate, not a stabilized temperature; increase it for more controlled experiments. See troubleshooting if a metric is unavailable.

Step 04

Inspect the CSVs

head -n 5 fibonacci-standard.csv
head -n 5 fibonacci-overtime.csv

Open the files in a spreadsheet or any CSV reader. The examples below use illustrative values, not actual measurements. Your values and available columns will depend on your machine.

Standard: one row per run

Language,Program,Powercap,Time_ms,Cores,cpu.Package_J,cpu.Temperature_C
Python, fibonacci, -1, 12000.000000, 12, 150.000000000000000000, 55.000000000000000000
Python, fibonacci, -1, 12100.000000, 12, 152.000000000000000000, 56.000000000000000000
Python, fibonacci, -1, 11900.000000, 12, 149.000000000000000000, 55.000000000000000000

Standard contains three data rows on a successful run. Time_ms is the elapsed time for each run, and cpu.Package_J, when available, is the package energy over that run.

Over-time: first three samples

Language,Program,Powercap,Timestamp_ms,Cores,cpu.Package_J,cpu.Temperature_C
Python, fibonacci, -1, 10200.000000, 12.000000000000000000, 100.125000000000000000, 50.000000000000000000
Python, fibonacci, -1, 20500.000000, 12.000000000000000000, 100.255000000000000000, 50.000000000000000000
Python, fibonacci, -1, 30800.000000, 12.000000000000000000, 100.383000000000000000, 51.000000000000000000

Over-time mode contains a row per sample. Timestamp_ms is elapsed time in milliseconds, and cpu.Package_J is the energy counter reading, not instantaneous power or energy since the previous sample. Counters may wrap or reset. The 10,000 µs interval is a pause between cycles, not a guaranteed sampling period.

Column availability and values vary with hardware and permissions. Package energy includes other activity and may overlap with other domains; it is not the energy of the Python process alone. A later failed reading is recorded as NOT_SUPPORTED.

Use your own program

Replace command in both TOML files with the command that runs your program in the foreground. Set language and program to labels that identify it in the CSV, and choose output names and metrics for your experiment. The command can run a program written in another language; those labels do not change how it is executed.

Generate new executables in new directories after changing the TOML files, then run them and inspect the CSVs as above. Make sure the command and its files are accessible from the directory in which you run the generated executable.
