Fibonacci, four ways

A sequential example: establish a temperature baseline, then measure and calibrate the same Python workload.

On this pageBefore runningConfigurationsRun the sequenceInspect resultsAdapt the example

01 / Prepare

Check the machine

The example configurations use Intel CPU, Intel GPU and NVIDIA GPU device libraries. Generation requires all declared libraries and their dependencies, including NVML, even if a GPU is unavailable. The Intel CPU must support the configured thermal and powercap operations. Check permissions for sensors, RAPL and power limits. Consult the repository requirements and review the TOMLs before running.

Plan the run

The sequence changes CPU power limits and can take a long time. It overwrites the explicitly configured cores_temperatures.txt baseline, appends to standard and over-time CSVs, and may replace the powercap calibration output. Save any existing results first.

02 / Configure

Four separate aspects

The configurations in configurations-generated/ explicitly name the same cores_temperatures.txt temperature baseline and declare their own devices and metrics:

  1. Temperature calibration — fibonacci-python-temperature-calibration.toml waits 60 seconds, then records one thermal reading and a sensors snapshot.
  2. Standard — fibonacci-python-standard.toml measures runs at the configured powercaps.
  3. Over-time — fibonacci-python-overtime.toml samples metrics during repeated runs.
  4. Powercap calibration — fibonacci-python-powercap-calibration.toml measures the saved baseline and the configured range of power limits.

The workload stages run Languages/Python/Fibonacci/fibonacci.py and declare CPU Package, Core and DRAM energy, NVIDIA GPU energy and temperature, and Intel GPU energy. Both GPUs can be measured in the same run. If a GPU cannot initialize, its columns contain NOT_SUPPORTED and the other measurements continue. Individual unavailable readings use the same value. Repetitions, pauses, limits and output names come from the TOMLs; inspect them for the current values.

03 / Execute

Run the sequence

From the repository root, with the permissions required by the configured devices:

bash scripts/run_fibonacci_sequence.sh

The script builds the optional device libraries, generates all four executables first, then runs them in the order above. It stops on failure. By default it creates generated-fibonacci-sequence; pass a different, non-existent directory as the optional argument:

bash scripts/run_fibonacci_sequence.sh my-new-sequence

The script runs from the repository root, so workload and output paths are relative to that directory. It does not automatically obtain elevated privileges.

04 / Inspect

Read the output

cat cores_temperatures.txt
head -n 5 fibonacci-python-standard.csv
head -n 5 fibonacci-python-overtime.csv
head -n 5 fibonacci-python-powercap-calibration.csv

These are the example paths; use the configured paths if you change the TOMLs. Use fresh CSVs when the metric schema changes. The temperature line represents one reading after the wait, not a time average. Standard counters are differences between the beginning and end of a run; over-time counters are raw samples. The powercap post-processor requires valid CPU Package readings and reports an error if they are unavailable, even though the CSV is written. See the output guide before interpreting energy readings.

Adapt the experiment

Change the workload command, labels, output paths, device declarations and settings as appropriate for your machine. Generate new executables after editing. Device libraries are optional: you can declare your own readers and hooks instead. See the measurement guide and weaver API.
