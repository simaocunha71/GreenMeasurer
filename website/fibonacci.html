Fibonacci, four ways

A sequential example: establish a CPU temperature baseline, then calibrate and measure the same Python workload.

On this pageBefore runningConfigurationsRun the sequenceInspect resultsAdapt the example

01 / Prepare

Check the machine

The sequence selects Intel CPU, Intel GPU and NVIDIA aspects and therefore needs their libraries and dependencies, including NVML. The weaver skips aspects it cannot build, but the sequence stops if it selects an unavailable flag. The CPU temperature sensor must be readable for calibration; NVIDIA temperature is measured without thermal control. Check hardware and permissions before running.

Plan the run

The sequence changes CPU limits and can take a long time. It overwrites cores_temperatures.txt, appends measurement CSVs and may replace the powercap output. The saved baseline (-1) is not necessarily uncapped.

02 / Configure

One aspect configuration

The aspect files in examples/aggregate and examples/over-time declare the metric aspects (with their mode) and a separate powercap control aspect. They do not contain workload or calibration paths.

The sequence script explicitly calibrates CPU temperature, then selects the Python Fibonacci 42 workload, CPU and GPU aspects, repetitions, pauses, power limits and output paths. Review the script and its hardware requirements before execution.

03 / Execute

Run the sequence

From the repository root, with the permissions required by the configured devices:

bash configurations-paper/run.sh

The script builds the optional device libraries and generates one executable for all modes. It runs CPU temperature calibration, powercap calibration, aggregate and over-time in that order. It stops on failure. By default it creates generated-fibonacci-sequence; pass a different, non-existent directory as the optional argument:

bash configurations-paper/run.sh my-new-sequence

The script runs from the repository root, so workload and output paths are relative to that directory. It does not automatically obtain elevated privileges.

04 / Inspect

Read the output

cat cores_temperatures.txt
head -n 5 fibonacci-python-aggregate.csv
head -n 5 fibonacci-python-overtime.csv
head -n 5 fibonacci-python-powercap-calibration.csv

These are the paths supplied by the script; change its arguments for other paths. Use fresh CSVs when the metric schema changes. The temperature line represents one reading after the wait, not a time average. Aggregate counters are differences between the beginning and end of a run; over-time counters are raw samples. The powercap post-processor requires valid CPU Package readings and reports an error if they are unavailable, even though the CSV is written. See the output guide before interpreting energy readings.

Adapt the experiment

Change aspect declarations in TOML and reweave. Change workload, labels, paths and measurement settings in the invocation or sequence script. Device libraries are optional: you can declare your own readers and hooks instead. See the measurement guide and weaver API.
